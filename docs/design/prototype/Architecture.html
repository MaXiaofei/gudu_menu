咕嘟小食单 · 个人全栈作品

技术架构

面向家庭的做饭助手：菜谱 → 食集 → 采购 → 做完回写余量。四端一套设计系统，后端按 DDD 限界上下文建模；咕嘟 Agent 用一句话串起跨页面操作，厨房圈补上家庭以外的内容来源。

1

系统总览

三端共用一套 API 与 design token；后端单体按限界上下文拆模块，用 ArchUnit 守住分层。向量检索与 embedding 在本地完成，对话模型走云端并带降级链。

部署 一台轻量服务器 · Docker Compose 双栈：staging 9090 / 13306 / 16379，prod 80·443 / 3306 / 6379，端口与网络隔离配置 Nacos 分环境 · 凭据只在 .env迁移 deploy.sh 按 sha256 登记，防重复执行
2

咕嘟 Agent

不给模型数据库：每个工具都是领域服务的薄适配层，复用租户校验。写操作先出确认卡、可撤销；画像只读注入；每一步都落 span，供后台排查与评测回流。

厨房圈 · Feed 推拉结合

普通作者写扩散保证读快，大 V 读扩散避免写放大；游标分页保证翻页期间有新帖也不重不漏；计数在 Redis 累加、定时回刷，点赞按唯一键幂等。

5

质量体系

每个功能按「功能代码 + 后端 E2E + Flutter 测试 + 小程序测试」四件套交付；AI 能力额外有评测集作为发布门禁。

ArchUnit 守护155

跨模块 Mapper 依赖冻结为基线，只减不增；新上下文零违规才能合入。

四件套测试1,192

后端单测 586、Flutter 364、小程序 139、后台 103，提交前全量跑绿。

E2E 连 staging38

核心链路与长尾接口 E2E，SSH 隧道连测试库；自建数据 E2E 前缀、可重复跑。

评测集门禁312

用例覆盖查询、写操作、拒答、注入攻击；工具选择正确率低于 90% 不可发布。

design token3 端

tokens.json 生成 Flutter / 小程序 / 后台主题，--check 防止手改漂移；素材管线同理。
