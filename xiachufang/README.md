# 下厨房 APP 调研

> 内部竞品调研。借鉴下厨房在菜谱/食材/采购/合集等**重合功能**上的产品设计,服务于咕嘟小食单的功能迭代。

## 为什么调研

咕嘟小食单与下厨房在以下功能上有明显重合:

- 菜谱(浏览/详情/创建)
- 食材(百科/管理)
- 采购清单
- 菜单/合集(咕嘟叫"食集")

下厨房是这类产品最成熟的标杆,其信息架构与交互细节值得借鉴。但咕嘟有明确差异化(餐程周计划、双轨三色库存、特殊人群适配、AI 智荐),**本调研是"借鉴"不是"照抄"**。

## 工作流(两层节奏)

> 不要"开发一步查一步"——太碎、效率低,还容易每次从零看抓不到重点。用两层节奏。

### 第一层:集中对照(一次性,现在做完)

- 把下厨房主要页面/流程快速走一遍
- 对照咕嘟已有功能,产出「功能对照总表」(`00-功能对照总表.md`)
- 决定每项:**借鉴 / 差异化不抄 / 不做**,并排优先级

这一层 1-2 小时集中做完,产出后沉淀,不用反复回头。

### 第二层:定向深挖(开发某功能时)

- 准备开发/重构某功能时,先看 `00-功能对照总表.md` 里相关的几行
- 把下厨房对应模块截图、分析交互细节,落到该模块的 `0X-xxx.md`
- 这份文档作为本次开发的原型参考,配合咕嘟自己的设计系统(`docs/design/tokens.json`)落地
