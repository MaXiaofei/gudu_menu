成功：列表移除该项 + SnackBar「已删除」

字段来源：列表项字段对应后端 Menu（name / servingCount / status：ACTIVE·进行中 / DONE·已完成 / createTime）。
状态可视化：进行中用琥珀胶囊 + 浅橙高亮卡，已完成用绿色胶囊，对应详情页头部的 _StatusChip。
列表项：食集名 + 菜数 + 份数 + 相对日期 + 封面缩略堆叠（最多 3 张）。
底部 Tab：5 项（菜谱 / 食集 / [凸起推荐 FAB] / 库存 / 我的），当前选中「食集」。
下拉刷新 / 上拉加载：pageSize=15，列表底部「上拉加载更多 / 没有更多了」。

① 左滑删除（已实现 · list_page.dart）：列表项用 Dismissible 包裹，仅 endToStart（从右向左滑）露出红色删除底；点击删除后弹二次确认（「确认删除食集「xxx」？该操作不可撤销」），确定才调 DELETE /menu/{id}——成功从列表移除 + SnackBar「已删除」，失败 SnackBar「删除失败」且卡片弹回。
点列表项 → 食集详情：进 menu-detail-cai.html（菜 tab 默认页），菜行可点进菜谱详情（从食集进、无底部按钮）。
② 菜数 + 封面图标（向后兼容 · list_page.dart）：菜数缩略堆叠遵循「有图显图，无图用菜名首字色块占位」（DESIGN.md §10.4，禁 emoji 顶图）。
  • 正常链路（后端新版）：列表接口直接返回 dishCount + covers（前 3 个菜的封面 URL），前端直接渲染图片堆叠。
  • 降级链路（后端旧版 / 菜无封面）：列表接口缺 dishCount 时，前端并发拉每个食集的详情（GET /menu/{id}）用 dishes.length 回填菜数；covers 为空时用详情里的 dishName 首字做 22×22 圆角色块堆叠（最多 3 个，如上「今晚的饭」的 番/紫/蒜）。静默失败，不阻断列表。
