# Proposal: 小程序正式版发布合规（个人信息保护 / AI 合规 / 平台审核）

**Change ID:** `mini-release-compliance`
**Created:** 2026-10-26
**Status:** Draft
**Roadmap:** #10（依赖 `multi-tenant-family`：租户隔离、越权、注销、账号合并在那边做）

---

## Problem Statement

2026-10-26 准备发布小程序正式版（1.0.0 已上传为开发版，未提审），全栈合规审计发现除多家庭隔离之外还有一批上线阻断与高风险项：

1. **内容安全缺失**：全仓无微信 `msgSecCheck` / `mediaCheckAsync`；AI 对话的输入输出、昵称、头像、上传图片均不审。
2. **同意不可证明**：后端没有同意记录（哪个版本、何时同意）；健康档案、不满 14 周岁儿童信息属敏感个人信息，没有单独同意。
3. **AI 合规缺口**：AI 对话 / 拍照识别 / 营养报告 / 智荐 / 周餐程等输出没有「AI 生成」显式标识，营养与特殊人群建议没有「仅供参考、不替代医嘱」提示；隐私政策写「不向模型发送健康档案原文」，实际 `AgentPrompts.java:32`、`ProfileConstraintPolicy.java:46`、`HouseholdAssembler.java:91` 会发送成员称呼 + 特殊人群 + 过敏。
4. **用户文件可被枚举**：`/uploads/**` 免登录，文件名为时间戳（`FileController.java:54,93`），照片含 EXIF 位置。
5. **协议是占位稿**：【运营主体】【注册地址】【联系邮箱】【生效日期】未填，收集清单漏了麦克风/语音、拍照识别、AI 对话记录、社区、发帖城市等。
6. **强制登录**：首屏即登录页，分享出去的菜谱也要先登录——微信审核常见驳回项。
7. **其他**：生产暴露 Swagger/knife4j；敏感字段明文；对话记录等无保留期清理；无个人信息副本导出。

## 用户已定决策（2026-10-26）

- 运营主体：**个人**，无法务——协议文本由我们按个人信息处理者为个人的口径起草，联系方式用邮箱。
- 发**完整版**，**保留 AI 功能**；**小程序关闭社区（厨房圈）**，App/网页端不受影响。
- 小程序**只用微信登录**；手机号仅作可选绑定（账号合并见 `multi-tenant-family` E.7）。
- **不做游客态**，保持首屏登录；新用户登录后引导设置头像昵称。

## Proposed Solution

1. **小程序关闭社区**：编译期开关 `FEATURE_COMMUNITY=false`，隐藏 Tab/入口，社区页面与 `pkg-community` 分包不打进小程序包；后端按请求来源（小程序 `X-Client: mp-weixin`）拒绝社区写接口。
2. **首次登录完善资料**：新账号（昵称仍为默认「微信用户」）登录后弹一次「设置头像和昵称」，用微信官方 `chooseAvatar` 按钮与 `type="nickname"` 输入框，可跳过；提交的昵称/头像先过内容安全（第 4 条）再保存。不新增游客态，保持现有「同意协议 → 微信静默登录」。
3. **同意记录与单独同意**：`consent_record(account_id, doc_type, doc_version, granted, channel, client_ip, created_at)`；登录前勾选协议后上报；首次填写健康档案 / 录入不满 14 周岁成员时弹窗单独同意（监护人），可撤回，撤回后删除对应字段。
4. **内容安全**：`ContentSecurity` 端口 + 微信实现（`msgSecCheck` v2 同步、`mediaCheckAsync` 异步回调）+ 规则兜底。覆盖：AI 对话输入（发模型前）与输出（返回前）、昵称、头像、上传图片、意见反馈。用户提交的内容审核不可用时**失败即拒绝**（昵称/头像）或降级到规则（AI 输入），AI 输出不通过时替换为安全提示。
5. **AI 合规**：所有 AI 产出位置加「AI 生成」标识组件；营养/健康/特殊人群相关页面加「仅供参考，不能替代医生或营养师建议」；Agent 首屏说明自己是 AI；AI 内容可一键反馈；发给模型的家庭信息最小化——成员称呼替换为「成员A/B」，只传特殊人群标签与过敏原，并在隐私政策如实披露。
6. **用户文件**：上传文件名改 UUID；去除图片 EXIF；`/uploads/**` 改为登录可读或短时签名 URL（分享图、公共菜谱图除外）。
7. **协议重写**：按个人主体定稿两份文本，覆盖全部收集项、AI 一节、敏感信息与儿童、第三方清单（DeepSeek/智谱、微信内容安全、腾讯云）、保存期限、权利行使（含注销、导出、账号合并）、联系邮箱；`LEGAL_VERSION` 升级，老用户重新同意。附带小程序后台「用户隐私保护指引」填写清单。
8. **数据生命周期与导出**：AI 对话记录 180 天、AI 调用日志 180 天、反馈 1 年后定时清理；`GET /account/me/export` 导出个人数据 JSON。
9. **生产收口**：prod 关闭 Swagger/knife4j；健康档案、手机号字段级加密（AES-GCM，密钥在 `.env`，openid 保留明文唯一索引用）。

## Scope

### In Scope
menu-api、menu-mini、docs/legal；Flutter 端仅同步协议文本、AI 标识与单独同意弹窗（App 不关社区）。

### Out of Scope
- 租户隔离、越权、注销、账号合并 → `multi-tenant-family`
- 生成式 AI 备案/登记、小程序类目选择 → 需用户在平台侧办理，本 change 只提供材料清单
- 社区（厨房圈）在小程序的重新开放

## Risks / Trade-offs

- `msgSecCheck` 需要用户 openid 且有频率限制：App 端（无 openid）只能走规则 + LLM 预审。
- 字段加密后无法按健康档案内容做 SQL 查询；目前没有这类查询。
- 协议版本升级会让所有老用户重新勾选一次。
- 个人主体能否开通 AI 相关类目以平台实际为准，代码合规不等于审核一定通过。
- 不做游客态：审核可能以「未体验功能前强制登录」驳回；届时再评估是否开放菜谱浏览。
