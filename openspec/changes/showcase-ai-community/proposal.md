# Proposal: 咕嘟 Agent、厨房圈与 AI 能力扩展

**Change ID:** `showcase-ai-community`
**状态:** Draft（2026-10-16）
**依赖:** `multi-tenant-family`（社区身份、家庭数据隔离）、`prototype-ui-rollout` P0（共享组件）、`backend-ddd-architecture`（新上下文原生四层）

## 为什么

咕嘟小食单目前解决的是「一个家庭内部」的做饭闭环：菜谱 → 食集 → 采购 → 做完回写余量。两个短板：

1. **操作路径长**：查「冰箱里的东西能做什么」要在余量、菜谱、智荐三个页面之间来回切；做完回写要逐项确认。
2. **没有家庭以外的内容来源**：公共菜谱库只靠后台审核投稿，用户之间没有交流，留存只靠工具属性。

这个项目同时是作者面试时展示的作品，需要覆盖能体现工程深度的方向：LLM Agent 工程化（工具调用、RAG、记忆、护栏、可观测、评测）、多模态、社区内容系统（Feed、计数、审核）。

## 做什么

| # | 能力 | 用户价值 | 能力展示点 |
|---|---|---|---|
| 1 | **咕嘟 Agent**（`agent-assistant`） | 用一句话完成跨页面操作：「冰箱里的能做什么」「把这三道加进周六食集」「麻婆豆腐做完了」 | Function Calling 编排、领域工具注册、写操作二次确认、SSE 流式、会话记忆与家庭画像、提示注入防护 |
| 2 | **厨房圈**（`kitchen-community`） | 晒菜、照着做、话题挑战；食记一键分享 | Feed 流（推拉结合）、Redis 计数与去重、游标分页、AI 预审 + 举报的内容治理 |
| 3 | **拍照识别**（`vision-intake`） | 拍冰箱/小票批量入库，拍菜谱截图导入 | 多模态大模型 + 结构化抽取、置信度分级、与食材字典对齐 |
| 4 | **一周餐程 + 营养报告**（`meal-plan-nutrition`） | 按家庭成员档案（高血压/宝宝辅食）生成一周食集，营养超标提醒 | 约束求解（规则过滤 + LLM 排布 + 校验回环）、营养计算 |
| 5 | **跟做模式**（`cook-mode`） | 做菜时大字步骤、语音「下一步」、多计时器 | 端侧语音唤醒/ASR、常亮与计时器、步骤内问 Agent |
| 6 | **Agent 可观测与评测**（`agent-observability`，后台） | 运营能看到 Agent 每次对话的调用链、成本，发版前跑评测 | Trace/Span 模型、成本核算、离线评测集与回归门禁 |

**导航调整（已与用户确认）：** 底部 Tab 改为「菜谱 / 食集 / 咕嘟（中间凸起）/ 厨房圈 / 我家余量」；「我的」移到各主 Tab 右上角头像；原「智荐」内容并入咕嘟首屏，「全部推荐」作为二级页保留。

## 不做

- 私信 / 群聊（内容安全成本高，与主线无关）
- 电商导购、带货链接
- 自训练模型；Agent 使用现有 DeepSeek 主模型 + 降级链，视觉用第三方多模态 API（供应商待定，与 `prototype-ui-rollout` P3-pending 的 OCR 选型合并决策）

- 前端：Flutter / 小程序新增约 13 个页面，主 Tab 导航全部调整；后台新增 3 页
