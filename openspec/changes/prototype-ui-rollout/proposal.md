# Proposal: 按高保真原型改版四端

**Change ID:** `prototype-ui-rollout`
**Created:** 2026-10-16
**Status:** Draft
**原型：** `docs/design/prototype/`（34 个画面，`index.html` 导览）
**关联：** `design-system-convergence`（token 与共享组件，本 change 承接其 §2 组件与 §5 页面打磨）、`multi-tenant-family`（家庭相关画面的前置）、`recipe-content-seed`（演示数据）

---

## Problem Statement

原型已定稿，但四端与之差距明显（2026-10-16 逐屏对照）：

- **图片缺位**：两端列表/食集大量用首字占位；Flutter 直接 `Image.network`，无缓存、无统一占位；**食材没有任何图片字段**；推荐接口用 `coverImage`、其他接口用 `coverUrl`，字段不统一。
- **页面结构**：详情无大图轮播与横滑步骤；食集详情只有 菜/备菜/聚餐 三个 Tab（原型 菜/备菜/采购/一起吃）；余量缺顶部统计与「先吃这些」；「我的」缺统计和最近食记；Notices、FamilyOnboard、FamilySwitch 三端都没有。
- **共享组件缺**：骨架屏、离线条、头像叠放、横向步骤卡、主图轮播、分段 Tab、家庭切换器。
- **后台**：公共菜谱库审核、账号与家庭、系统健康三页缺失；仪表盘、营养、反馈、AI 用量四页只做了一部分。
- **后端缺口**（原型新增能力，无任何 change 规划）：注销冷静期、数据导出、登录设备、新类型消息（邀请/反馈已处理/投稿通过）、反馈报错编号与回复、投稿审核状态、审计日志、AI 成本预算与后台改限额、系统健康与报错聚合、短信验证码登录、拍小票入库、拍照识别菜谱。

## Proposed Solution

分四个阶段，每阶段四端同步交付（四件套）：

| 阶段 | 内容 | 依赖 |
|---|---|---|
| **P0 基础** | 素材管线（食材插画、默认头像、App 图标光栅化打包）、`ingredient.icon_key`、图片字段统一 `coverUrl`、共享组件（DishImage / IngredientIcon / AvatarStack / HeroGallery / StepCarousel / Skeleton / OfflineBanner / SegmentTabs）| 无 |
| **P1 主链路页面** | 菜谱列表、菜谱详情、做完确认、智荐、我家余量、入库、食集列表、食集详情 4 Tab（采购并入）、备菜、采购、清单转图片、食记、写菜谱、我的、主题、反馈、状态规范、登录（视觉 + 协议前置）| P0、现有接口 |
| **P2 家庭** | 创建/加入家庭、切换家庭、成员与角色、邀请消息 | `multi-tenant-family` |
| **P3 生产级能力** | 消息中心、隐私与账号（导出/设备/注销冷静期）、反馈报错编号与回复、投稿公共库与审核、后台 7 页补齐、审计日志、AI 预算、系统健康 | 后端新接口（本 change） |
| **P3-待定** | 短信验证码登录、拍小票、拍照识别菜谱 | **需用户决策供应商**（短信/OCR/视觉模型与费用），决策前不开工 |

## 设计原则（与原型一致）

- 主按钮 `primaryDeep` 底白字；`caption` 色只用于 ≥18px；小字辅助文字用 `body`。
- 有图的位置一律有图；图片缺失/加载失败回退首字占位（统一组件，不再各页自写）。
- 每个数据页三态：骨架屏 / 空态（插画 + 下一步）/ 错误（重试 + 报错编号）；离线顶部条不挡操作。
- 颜色/字号/间距只用 token；两套皮肤都要截图验收。

## Out of Scope

- 暗色模式（沿用 design-system-convergence 决策）。
- 内容版权替换（见 `recipe-content-seed`）。
- 社区化（公开评论、关注等）。

## Success Criteria

- 每个原型画面在 Flutter 与小程序有对应页面，截图与原型并排验收通过（两套皮肤）。
- 后台 7 页齐全，接口无 mock。
- 首字占位只在图片缺失时出现；页面目录 0 处裸色值/裸字号（守护规则）。
